# PLAN-137: Helm Packaging & Release Governor

## 1. Architectural Strategy

- **Layer-0 Purity**: Uses Node.js native `spawnSync` from `node:child_process`, `node:fs`, `node:path`. Zero third-party npm libraries.
- **Hexagonal Boundary**: `EosHelmReleaseGovernor` coordinates between `helm` binary, `EosOpaPolicyGovernor`, and `EosKubectlClusterInspector`.
- **In-Memory YAML Multi-Doc Parsing**: Parses multi-document YAML outputs generated by `helm template` into distinct resource objects using pure regex/string splitting, mapping each resource into JSON for OPA evaluation without requiring external YAML libraries.
- **Fail-Closed 5-Stage Gate**:
  1. Context Guard (Context must match `/^kind-/`).
  2. Helm Lint (`helm lint --strict`).
  3. Template & OPA Policy Evaluation (`security_baseline.rego`).
  4. Server-Side Dry-Run (`helm upgrade --install --dry-run=server`).
  5. Atomic Apply (`helm upgrade --install`).

## 2. Alternatives Considered & Rejected

- _Alternative A: Using an npm package like `helm-client` or `yaml`_. Rejected due to Law V (Zero Runtime Dependencies) and supply chain vulnerability risks.
- _Alternative B: Deploying raw templates directly with `kubectl apply`_. Rejected because enterprise release lifecycles require Helm chart release metadata, atomic rollbacks (`helm rollback`), and revision history.

## 3. Risk Assessment & Mitigations

- _Risk_: `helm` binary missing from host.
  - _Mitigation_: Fail-soft check verifying `helm` availability with clear installation diagnostic if missing.
- _Risk_: YAML multi-document parsing errors on complex templates.
  - _Mitigation_: Strip comments, split on `/^---(?:\r?\n|$)/m`, and parse key resource properties (`apiVersion`, `kind`, `metadata`, `spec`) deterministically.

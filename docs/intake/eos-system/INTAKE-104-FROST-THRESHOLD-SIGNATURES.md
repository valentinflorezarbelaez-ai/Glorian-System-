## 1. Problem Statement

Autonomous multi-agent swarms, decentralized treasuries, and multi-validator consensus protocols require threshold authorization where no single agent holds the master private key, but any authorized threshold $t$ of $n$ participants can sign transactions.

Standard multi-signature schemes (multisig) require publishing $t$ separate signatures and public keys, linearly inflating ledger size ($O(t)$) and exposing individual signer identities on-chain.

RFC 9591 (FROST - Flexible Round-Optimized Schnorr Threshold Signatures) solves this by enabling $t$-of-$n$ participants to collaboratively evaluate a single, standard Schnorr signature $(R, z)$ that is byte-for-byte indistinguishable from a regular signature generated by a single private key.

## 2. Requirements & Inviolable Constraints

1. **Zero External Runtime Dependencies (EOS Law V)**: Pure TypeScript using Node 24 BigInt arithmetic over secp256k1 curve parameters ($y^2 = x^3 + 7 \pmod p$, group order $q$).
2. **RFC 9591 Security Standards**: Protection against rogue-key attacks, forgery under concurrent sessions (via binding factors $\rho_i$), and anti-ROS attack security.
3. **Subset Flexibility**: Any subset $S \subseteq \{1, \dots, n\}$ with $|S| \ge t$ can produce a valid signature using Lagrange interpolation over $\mathbb{Z}_q$.
4. **O(1) Verification**: Standard Schnorr verification $z \cdot G \stackrel{?}{=} R + c \cdot PK$ in sub-milisegundo ($< 2$ ms).
5. **Module Line Count Limit**: Strictly $\le 800$ lines.

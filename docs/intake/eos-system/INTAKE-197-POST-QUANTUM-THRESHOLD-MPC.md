# EOS Intake & Context Record: INTAKE-197 (SPEC-335 / CHANGE-197)

## 1. Context & Business Intent

- **System**: Glorian System (Control Plane & Layer-0 Core Engine)
- **Domain**: Threshold Secret Sharing, Lattice-Based (Ring-LWE) Additively Homomorphic Encryption & Secure Multi-Party Aggregation
- **Objective**: Implement a pure Layer-0 TypeScript reference engine (`EosPostQuantumThresholdMpcCore`) with zero external runtime dependencies that lets `N` parties contribute private integer vectors, aggregates them homomorphically without decrypting individual contributions, and decrypts only the aggregate when at least `T` of `N` key-share holders cooperate.
- **Reference Material**:
  - Adi Shamir: _How to Share a Secret_ (CACM 1979) — threshold secret sharing over a prime field.
  - Lyubashevsky, Peikert & Regev: _On Ideal Lattices and Learning with Errors over Rings_ (EUROCRYPT 2010).
  - Fan & Vercauteren: _Somewhat Practical Fully Homomorphic Encryption_ (BFV, IACR ePrint 2012/144).
  - Bonawitz et al.: _Practical Secure Aggregation for Privacy-Preserving Machine Learning_ (CCS 2017).
  - NIST FIPS 203 (ML-KEM) — context for lattice-based post-quantum cryptography.

## 2. Core Functional Requirements

1. **Shamir Threshold Secret Sharing** over the Mersenne prime field `F_q`, `q = 2^61 - 1`, with Lagrange reconstruction at zero.
2. **Share Integrity Commitments**: SHA-256 hash commitments bound to each share; tampered shares are rejected before reconstruction.
3. **Ring-LWE Encryption (BFV-style)** over `R_q = Z_q[x]/(x^n + 1)` with ternary secrets and centered-binomial noise, supporting vector packing of up to `n` slots.
4. **Additive Homomorphism**: ciphertext + ciphertext addition and ciphertext × public-scalar multiplication, modulo the plaintext modulus `t`.
5. **Threshold Decryption**: the ring secret key is Shamir-shared coefficient-wise; any `T` partial decryptions combine via Lagrange coefficients into the plaintext aggregate; fewer than `T` are rejected.
6. **Formal Model (TLA+ Model 79)**: bounded model of the aggregation protocol proving threshold safety, aggregate correctness and submission freezing.

## 3. Honest Scope Limitations (Mandatory)

- **Not production cryptography.** Default parameters (`n = 64`) provide no meaningful security level. Production deployments require audited libraries (e.g. OpenFHE, Microsoft SEAL, liboqs) and parameters validated against the Homomorphic Encryption Standard.
- **Trusted dealer.** Key shares are generated by a single dealer; no distributed key generation (DKG).
- **No smudging noise** in partial decryptions; partial decryptions may leak information about key shares to the combiner.
- **Hash commitments, not verifiable secret sharing.** Commitments detect tampering against published digests; they do not prove share consistency (Feldman/Pedersen VSS out of scope).
- **Not constant-time.** BigInt arithmetic is subject to timing side channels.

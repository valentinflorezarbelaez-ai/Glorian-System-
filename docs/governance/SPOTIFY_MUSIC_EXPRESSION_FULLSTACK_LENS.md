## Purpose

Music Expression builds the tools artists use to show who they are on Spotify and connect with fans. A song is not only a track in a list — it can carry Canvas loop visuals, music videos, vertical artist video, release countdowns, and shared listening parties on release day.

This JD is the **full-stack product bar** for Glorian Spotify work and the concrete stack to train against when preparing for Spotify Music engineering roles.

Companion lens: `SPOTIFY_AUTHORIZATION_PLATFORM_LENS.md` (Platform AuthZ, Toronto). Together they define:

| Track | Org signal | Stack core | Product truth |
| --- | --- | --- | --- |
| Platform Authorization | Secure who can manage creator presence | Java backend, RDBMS, distributed AuthZ | Multi-principal permissions |
| Music Expression | How artists appear and fans experience music | Java + React/TypeScript + APIs | Artist → fan creative journey |

## What “working to get / win this Spotify job” means

1. **Product excellence** — every change must improve how artists show up and how fans enjoy music (or the platform that enables that).
2. **Their stack, not adjacent theater** — deliberate depth in **Java** (services/APIs) and **React + TypeScript** (UI/SDKs), plus how APIs glue them.
3. **Full-stack narrative** — ability to reason across backend, frontend, and the contracts between them in one system story.
4. **Creative + technical judgment** — comfort at the intersection of technology, creativity, and culture.
5. **Growth + mentoring signal** — curiosity, experimentation, clear communication, lifting teammates.
6. **Ops/infra awareness** — infrastructure-adjacent experience is a plus; Soundcheck/canary/reliability still apply.
7. **Honest scope** — Glorian Layer-0 stays pure Node/TS control plane; job prep means **parallel Java/React practice artifacts** and mapped concepts — never fake “we run Spotify production Music Expression.”

## Stack priors (train / evaluate against)

### Backend (must)
- Java service design, build, operate
- Scalable APIs; product requirements at the service boundary
- Performance, reliability, evolution of architecture

### Frontend (must)
- React + TypeScript
- UI layers and **frontend SDKs**
- End-to-end UX quality, accessibility, and client performance

### Glue (must)
- API design that connects user experiences to internal infrastructure
- Observability, failure modes, backwards compatibility

### Plus
- Infra-related technologies (deploy, CI, containers, cloud primitives — concepts)
- Agile delivery, continuous learning culture
- Mentorship / collaborative team building

## Dual-JD operating rule for Glorian

When building or auditing Spotify-aligned product work:

1. Apply **Music Expression** if the surface is artist expression, release-day experiences, media/Canvas/video, fan-facing creative tools, or full-stack Java+React delivery.
2. Apply **Authorization Platform** if the surface is permissions, teams, partners, or creator admin access control.
3. Always keep institutional pillars (Soundcheck, canary, Golden Paths) — they are necessary, not sufficient.
